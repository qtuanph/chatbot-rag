# 2.5 — Analytics Workflow

Analytics hiện tại tập trung vào **usage model** và **feedback chất lượng**, không còn dựa trên persisted chat session.

## Mục tiêu

- theo dõi usage theo tenant
- xem tenant nào tốn nhiều tài nguyên hơn
- tính quota / rate limit
- theo dõi latency, token và cost
- theo dõi like / dislike để cải thiện chất lượng

## Nguồn dữ liệu chính

- `ai_model_usage`
- `chat_feedback`

## Những loại usage được ghi

| `model_type` | Ý nghĩa |
|---|---|
| `llm` | gọi model sinh câu trả lời |
| `embedding` | gọi model embedding |
| `reranker` | gọi model rerank |

## Dữ liệu usage quan trọng

| Cột | Ý nghĩa |
|---|---|
| `tenant_id` | tenant sở hữu usage |
| `user_id` | user nội bộ nếu có |
| `prompt_tokens` | token đầu vào |
| `completion_tokens` | token đầu ra |
| `total_tokens` | tổng token |
| `cost_micros_vnd` | tiền lưu dạng integer micro-VND |
| `latency_ms` | độ trễ |
| `endpoint` | route hoặc flow đã gọi |

## Dữ liệu feedback

Feedback chat lưu:

- `like` / `dislike`
- `query_text`
- `assistant_answer`
- `document_ids`
- `section_ids`
- `citations`
- `llm_model`, `embedding_model`, `reranker_model`

## Endpoint chính

| Endpoint | Mục đích |
|---|---|
| `GET /analytics/stats?days={n}` | thống kê chung theo khoảng thời gian (`days`: 1=hôm nay, 7=tuần, 30=tháng, mặc định 30) |
| `DELETE /analytics/stats` | reset usage dev (Platform Admin only) |
| `GET /analytics/me/usage` | usage của user hiện tại (cửa sổ 1, 7, 30 ngày) |
| `GET /admin/users/usage` | thống kê theo user |
| `GET /admin/users/{user_id}/usage` | chi tiết user |
| `GET /admin/tenants/usage` | thống kê theo tenant |

`GET /analytics/stats` trả về cấu trúc tổng hợp:

- `messages`: số lượt hoàn thành câu trả lời (chỉ tính `model_type == 'llm'`, không tính gộp embedding/reranker).
- `total_tokens_in`, `total_tokens_out`, `total_tokens`: tổng token tiêu thụ.
- `avg_latency_ms`: độ trễ trung bình tính bằng mili-giây.
- `by_model_type`: thống kê chi tiết chia theo từng loại model (`llm`, `embedding`, `reranker`).
- `daily_by_model_type`: xu hướng biến thiên theo ngày của từng loại model.
- `recent_requests`: danh sách 50 lượt gọi model gần nhất (kèm latency, tokens, status).
- `feedback_summary`: tổng like, dislike, tỷ lệ dislike, và top câu hỏi/tài liệu bị dislike.

## Cấu trúc UI Phân hệ Analytics (Sub-routes)

Frontend chia nhỏ giao diện Analytics thành 4 sub-routes chuyên biệt để tải trang nhanh và trực quan:

| Route Webapp | Nội dung hiển thị |
|---|---|
| `/admin/analytics` | Tổng quan: 4 KPI chính (Lượt hỏi, Tokens, Chi phí VND, Độ trễ), Thẻ chi tiết từng loại Model, và Bảng thiết lập đơn giá VND/1M token |
| `/admin/analytics/trends` | Biểu đồ xu hướng: Area Chart thể hiện biến thiên Token Vào/Ra và Lượt gọi theo ngày |
| `/admin/analytics/tenants` | Phân bổ tài nguyên theo Tenant: Bảng DataTable hiển thị chi phí, token tiêu thụ, tỷ lệ % và hạn ngạch của từng tenant |
| `/admin/analytics/logs` | Nhật ký truy vấn gần đây: Bảng lịch sử 50 request mới nhất với mã định danh, model, latency và tokens |

## Quy tắc tiền tệ

- chuẩn tiền tệ là `VND`
- không lưu `float`
- dùng `cost_micros_vnd` (1 VND = 1,000,000 micros)
- đơn giá hiển thị và tính toán: VND trên 1 triệu tokens (VND/1M tokens)

## Những gì đã bỏ

- `total_sessions`
- analytics dựa trên `chat_sessions`
- analytics dựa trên persisted transcript

## Lưu ý thực tế

Embedding và reranker có thể không luôn có token đẹp như LLM.

UI phải chấp nhận:

- `completion_tokens = 0`
- token ước tính cho embedding hoặc reranker
